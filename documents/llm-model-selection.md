# LLM 모델 선정 기록 — 2026-10-07

> NPC 대화에 쓰는 OpenAI 모델을 `gpt-4o-mini` / `gpt-4o`에서 **`gpt-6-luna`**로 바꾼 과정과 이유를 정리한다.
> 설정 위치: `llm/config.py`, 호출: `llm/nodes/chat_node.py`의 `get_llm()`

## 결론

| 구간 | 이전 | 변경 후 |
|---|---|---|
| 1~2번째 루프 | `gpt-4o-mini` (temperature 0.7) | **`gpt-6-luna` · 추론 `none`** |
| 3번째 루프 (진실 접근) | `gpt-4o` (temperature 0.7) | **`gpt-6-luna` · 추론 `medium`** |
| 임베딩 (RAG·이미지 검색) | `text-embedding-3-small` | 변경 없음 |

## 1. 배경

- 기존 두 모델(`gpt-4o`, `gpt-4o-mini`)은 2024년 모델이고, OpenAI 공식 가격표에서 **legacy**로 분류되어 있다. 종료 예정 공지는 아직 없다.
- 이 게임은 실시간 공포 채팅이라 **응답 속도가 몰입감에 직결**된다. 한 루프에 NPC당 최대 20턴을 주고받는다.
- 동시에 NPC는 루프별 정보 공개 제한, 감정 수치에 따른 말투, 숨겨야 할 진실 같은 규칙이 많아서 **규칙 준수**도 중요하다.

## 2. 모델 후보 (OpenAI 공식 가격표 기준, 1M 토큰당)

| 모델 | 입력 | 캐시 입력 | 출력 | 공식 설명 / 특징 |
|---|---|---|---|---|
| gpt-6-astra | $10.00 | $1.00 | $50.00 | 가장 강력한 모델. 추론 `none` 미지원 |
| gpt-6.1-sol | $2.00 | $0.10 | $10.00 | Astra에 가까운 성능, 더 저렴. 추론 `none`·`minimal` 미지원 (최소 `low`) |
| **gpt-6-luna** | **$0.10** | **$0.01** | **$0.50** | 가장 효율적, 대량 처리용. 추론 `none`~`max` 지원 |
| gpt-5-mini | $0.25 | $0.025 | $2.00 | 이전 세대 소형 |
| gpt-4o *(legacy, 기존)* | $2.50 | $1.25 | $10.00 | |
| gpt-4o-mini *(legacy, 기존)* | $0.15 | $0.075 | $0.60 | |

- 실시간 채팅에 비해 성능이 과한 `gpt-6-astra`(출력 $50)는 제외했다.
- 최종 비교는 **luna**(가장 저렴·빠름)와 **sol**(고성능 대안)로 좁혔다.

### GPT-6 계열 호출 시 주의점 (공식 문서)

- GPT-6 계열은 모두 **추론(reasoning) 모델**이다. 추론 강도(`reasoning_effort`)를 고를 수 있다.
- **추론 토큰은 출력 토큰으로 청구**되고, 출력 토큰 한도(`max_completion_tokens`)에서도 차감된다.
- `temperature` 지원 여부는 공식 모델 문서에 명시되어 있지 않아 **설정하지 않았다.**

## 3. 비교 테스트

조건: 실제 NPC 프롬프트와 질문을 그대로 사용, 장면당 1회 호출(평균 시간만 3회). 플레이어 이름 '이서진', 성별 남성.

### 3-1. 1차 — 응답 속도 (기존 프롬프트, 엄마 "엄마, 내일이 무슨 날이에요?", 3회 평균)

| 모델 | 응답 시간 | 평균 |
|---|---|---|
| gpt-4o-mini (기존) | 1.8 / 1.5 / 1.5초 | 1.6초 |
| gpt-6-luna · none | 1.6 / 1.5 / 1.9초 | 1.7초 |
| gpt-6.1-sol · low | 4.4 / 4.0 / 3.4초 | 3.9초 |

→ luna는 기존과 속도가 같고, sol은 약 2.4배 느렸다.

### 3-2. 2차 — 품질 (기존 프롬프트, 5개 장면, luna none vs sol low)

| | luna | sol |
|---|---|---|
| 응답 속도 | 평균 약 1.9초 | 평균 약 3.6초 |
| 대답 길이 | 짧음 | 5개 장면 모두 더 김 |
| 공포 분위기 | 박도원 장면에서 불길함을 잘 살림 | 가끔 너무 친절함 |
| 규칙 준수 | 차서연이 박주원의 '살해'를 사실처럼 단정 (설정상 의심만 해야 함) | 의심과 모호함 유지, 질문으로 되받음 |

→ 이 시점에는 sol의 규칙 준수가 나았다. 이후 프롬프트 개선(`documents/prompt-engineering.md`)으로 luna의 정보 과다 노출이 줄었다.

### 3-3. 3차 — 추론 강도 비교 (개선된 프롬프트, 4개 장면)

장면: 엄마(루프3) "나영이 정말 사고였어요?" / 김도현(루프2) "김하윤이 누구예요?" / 차서연(루프3) "박주원 죽음에 대해 뭘 알아요?" / 박도원(루프1) "택배요? 저 시킨 거 없는데요."

| 설정 | 평균 응답 시간 | 평균 출력 토큰 (그중 추론) | 1턴 비용 |
|---|---|---|---|
| luna · none | 1.9초 | 42 (0) | 약 $0.0003 |
| luna · low | 2.1초 | 98 (44) | 약 $0.0003 |
| **luna · medium** | **2.8초** | 166 (109) | **약 $0.0003** |
| sol · low | 4.6초 (최대 7.3초) | 57 (0) | 약 $0.0057 (약 19배) |

장면별 관찰:
- **엄마:** sol이 가장 문학적("사고라고 부른 건… 너까지 잃을까 봐 엄마가 붙인 이름이었어"). luna low는 3문장으로 길어져 '1~2문장' 규칙을 어김.
- **김도현:** sol이 단서를 가장 잘 흘렸지만("마지막 상담") 7.3초 걸림. luna medium도 압박감이 좋음("정말 모르십니까, 아니면 모르는 척하시는 겁니까?").
- **차서연:** luna none이 박주원의 죽음을 '사고'로 잘못 말함. 나머지는 내용이 맞음.
- **박도원:** luna medium이 가장 불길함("안에 든 건 확인 안 하셔도 되겠습니까?"). sol은 사투리가 섞임.

## 4. 결정과 이유

1. **1~2번째 루프: luna · none**
   - 기존 gpt-4o-mini와 응답 속도가 같다 (약 1.7~1.9초).
   - 비용은 더 낮다 (입력 $0.10 vs $0.15, 출력 $0.50 vs $0.60).
   - 이 구간은 진실을 거의 드러내지 않아서, 추론 없이도 충분하다. low는 품질 차이가 크지 않은데 가끔 말이 길어졌다.
2. **3번째 루프: luna · medium**
   - 진실이 조금씩 드러나는 구간이라 규칙 준수가 중요해서 추론을 켰다.
   - sol low와 비교해 품질 차이에 비해 **속도(2.8초 vs 4.6초)와 비용(약 1/19)** 차이가 컸다.
   - sol은 응답이 7초를 넘는 경우도 있어서 채팅 몰입감에 불리했다.

## 5. 설정 상세 (`llm/config.py`)

```python
LLM_MODEL_DEFAULT = "gpt-6-luna"
LLM_MODEL_HEAVY   = "gpt-6-luna"
LLM_REASONING_EFFORT_DEFAULT = "none"
LLM_REASONING_EFFORT_HEAVY   = "medium"
LLM_MAX_TOKENS_DEFAULT = 800    # 추론 없음 → 대답 길이만
LLM_MAX_TOKENS_HEAVY   = 4000   # 추론 토큰 몫까지 여유
# temperature: 설정하지 않음 (GPT-6 지원 여부 미명시)
```

- **sol로 되돌리기:** `LLM_MODEL_HEAVY = "gpt-6.1-sol"`, `LLM_REASONING_EFFORT_HEAVY = "low"` (sol은 `none`·`minimal`을 쓰면 400 오류).

## 6. 한계와 후속 확인

- 장면당 1회만 호출한 결과라 경향 정도로 봐야 한다. 실제 플레이로 체감 속도와 품질을 확인할 것.
- 응답 시간은 OpenAI 서버 상황에 따라 달라질 수 있다.
- 캐릭터 프롬프트는 매 턴 같은 앞부분이 반복되어 **캐시 입력 할인**이 적용되므로, 실제 비용은 위 추정보다 낮다.
