# NPC 프롬프트 개선 기록 — 2026-10-07

> NPC 4명(엄마, 차서연, 김도현, 박도원)의 시스템 프롬프트를 OpenAI 공식 프롬프트 가이드 기준으로 다시 구성한 기록이다.
> 관련 파일: `llm/prompts/base.py`, `llm/prompts/{umma,cha_seoyeon,kim_dohyun,park_dowon}.py`, `llm/vector_store/rag_inject.py`
> 치키 프롬프트(`llm/prompts/executor.py`)는 현재 게임에서 쓰이지 않아 대상에서 뺐다.

## 1. 기준: OpenAI 공식 프롬프트 가이드

출처: [OpenAI Prompt engineering guide](https://developers.openai.com/api/docs/guides/prompt-engineering), [Best practices for prompt engineering with the OpenAI API](https://help.openai.com/en/articles/6654000-best-practices-for-prompt-engineering-with-openai-api)

| 공식 가이드 내용 | 이 프로젝트에 적용 |
|---|---|
| **역할 우선순위:** `developer`(system) 메시지는 `user` 메시지보다 우선한다 | 캐릭터 규칙은 모두 system 메시지에 둔다 |
| **developer 메시지 구성:** Identity → Instructions → Examples → Context 순서 | 같은 순서로 재구성 |
| **서식:** 계층은 Markdown 제목·목록, 내용의 경계는 XML 태그 | `#`/`##` 제목 + `<character_profile>`, `<example>` 등 |
| **Few-shot:** 예시는 developer 메시지 안에 XML 태그(`<user_query>`, `<assistant_response>`)로 넣는다 | 대본 형식 예시를 XML로 자동 변환 |
| 명확하고 구체적인 지시, 출력 형식 명시 | "1~2문장, 대사만 출력" 등을 Instructions 맨 앞에 배치 |
| 예시는 많은 것보다 **잘 고른 것**이 중요 | 캐릭터당 예시를 23~35개 → 7개로 정리 |

> 처음에는 "예시를 user/assistant 메시지 쌍으로 넣는다"는 방식을 검토했지만, 공식 가이드는 developer 메시지 안의 XML 예시를 권장한다. 메시지 쌍으로 넣으면 모델이 예시를 **실제로 있었던 대화로 착각할** 위험도 있어서 쓰지 않았다.

## 2. 개선 전 문제

| 문제 | 내용 |
|---|---|
| 화자 접두어 출력 | 예시가 "차서연: …", "유저: …" 같은 대본 형식이라, 모델이 대답 앞에 "차서연:"을 붙일 위험이 있었다. 이를 막는 금지 규칙을 따로 두고 있었다 |
| 예시가 너무 많음 | few-shot이 프롬프트의 55~64% (약 2,200~2,900 토큰) |
| 예시를 베낌 | luna가 예시 대사 "내일 네 동생 기일이잖아. 엄마는 며칠 전부터…"를 거의 그대로 반복 |
| 루프 제한과 충돌 | 예시가 모든 루프에 똑같이 들어가서, 후반부 진실이 담긴 예시(엄마 "네 곁에 있던 애들이 자꾸 아팠어" 등)가 루프1에도 노출됐다 |
| 규칙이 묻힘 | 중요한 규칙(루프별 공개 제한, 숨겨야 할 것)이 긴 예시 사이에 파묻힘 |
| 고정 조사 | 템플릿의 `{player_name}가`, `{player_name}를` 때문에 "이서진가", "이서진를" 같은 문장이 54곳 생김 |
| 호칭 혼동 | 엄마 프롬프트에서 "우리 애"가 죽은 딸(나영)과 플레이어를 모두 가리켰다 |

## 3. 변경 내용

### 3-1. 프롬프트 구조 (`base.py` `build_system_prompt()`)

```
# Identity        정체성 + <character_profile>(기본 성격·말투, 각 캐릭터 파일의 BASE_PERSONALITY)
# Instructions    응답 형식 → 호칭 → 역할 범위 → 절대 말하면 안 되는 것
                  → 이번 루프 정보 공개 제한 → 현재 내면 상태(<current_state>, <tone_guidance>)
# Examples        <example> 블록들 ("실제 대화가 아니며 그대로 반복하지 말 것" 명시)
# Context         <game_state>(루프, 이름, 성별, 단서) + RAG 참고 정보(<reference_story>)
```

### 3-2. Few-shot을 XML 예시로 자동 변환 (`few_shot_to_xml()`)

캐릭터 파일의 예시는 지금처럼 **대본 형식으로 작성**하면 된다. 프롬프트를 만들 때 자동으로 변환된다.

```
[상황 1 - …]                       <example>
[대화 3 - … (루프2부터)]     →      <situation>상황 1 - … / 대화 3 - …</situation>
유저: 내일 뭐 있는데?                <user_query>내일 뭐 있는데?</user_query>
엄마: …서진아. 너는 참…              <assistant_response>…서진아. 너는 참…</assistant_response>
                                    </example>
```

- 화자 이름을 지워서, 모델이 **대사만 출력**하는 형식을 따라 하게 했다. → 화자 접두어 문제 해결
- NPC 대사가 연달아 나오면 한 `<assistant_response>`에 합친다.

### 3-3. Few-shot 정리와 루프 표시

- 캐릭터당 **7개**만 남겼다. 고른 기준: 기본 말투 / 회피·넌지시 흘리기 / 감정 고조 1개 / 외부 질문 반응 / 치키 언급 반응 / 진실 접근 장면
- 진실에 가까운 예시에는 제목 끝에 **`(루프N부터)`**를 붙였다. N번째 루프부터만 프롬프트에 들어간다.
- 빠진 예시 원본은 `llm/prompts/few_shot_archive/{캐릭터}.md`에 보관했다.

| 캐릭터 | 루프1 / 2 / 3 예시 수 | 루프 표시가 붙은 예시 |
|---|---|---|
| 엄마 | 5 / 6 / 7 | 상황2-대화6 (루프2), 상황3-대화7 (루프3) |
| 차서연 | 5 / 6 / 7 | 상황4-대화4 (루프2), 상황5-대화8 (루프3) |
| 김도현 | 3 / 6 / 7 | 상황3-대화1·상황4-대화1·상황7 (루프2), 상황5-대화5 (루프3) |
| 박도원 | 4 / 6 / 7 | 상황4-대화5·상황6 (루프2), 상황4-대화7 (루프3) |

- 김도현 상황7("죽은 하윤이")과 박도원 상황6("선생님은 정말 모르시는 거 맞지요?")은 치키 언급 예시지만 내용상 루프2부터로 표시했다.
- 루프 표시 기준은 `llm/vector_store/data/world/세계관.md`의 루프별 공개 범위다 (김하윤 이름·과거 단서는 루프2, 가해자 암시·직접 추궁은 루프3).

### 3-4. RAG 참고 정보 위치 (`rag_inject.py`)

- 이전: 프롬프트 안의 `"=== 기본 성격"` 글자를 찾아 그 앞에 끼워 넣음
- 변경: **Context 맨 끝**에 `<reference_story>` 태그로 덧붙임 (공식 가이드상 참고 정보는 Context에 속함)

### 3-5. 조사 자동 보정 (`fix_josa()`)

- 프롬프트를 만든 직후, 플레이어 이름 바로 뒤의 조사를 받침에 맞게 고친다.
  - 이/가, 을/를, 은/는, 과/와, 으로/로 (ㄹ 받침 + 로)
  - 예: 이서진가 → 이서진**이**, 정재희이 → 정재희**가**
- 캐릭터 파일은 지금처럼 `{player_name}가`로 써도 된다.

### 3-6. 엄마 호칭 정리 (`umma.py`)

- 딸(나영)을 초반에 부르는 말에서 "우리 애"를 빼고 "그 아이", "네 동생", "딸아이"로 정리했다.
- "우리 애"는 플레이어를 부를 때만 쓴다 (성별 '기타'일 때 자녀 호칭).

## 4. 결과

| 캐릭터 | 개선 전 | 개선 후 (루프1 / 2 / 3) |
|---|---|---|
| 엄마 | 약 4,000 토큰 | 2,570 / 2,715 / 2,861 |
| 차서연 | 약 4,560 | 2,331 / 2,431 / 2,537 |
| 김도현 | 약 3,840 | 1,960 / 2,368 / 2,513 |
| 박도원 | 약 4,200 | 2,366 / 2,724 / 2,835 |

- 프롬프트 길이 **30~50% 감소**
- 화자 접두어가 붙은 대답 없음 (4개 장면 확인)
- luna의 정보 과다 노출 감소: 개선 전 차서연은 "주원이는 살해당했고"라고 단정했지만, 개선 후에는 "저는 그렇게 보지 않습니다"로 의심만 유지했다 (장면당 1회 확인)

## 5. 유지보수 가이드

- **예시 추가:** 캐릭터 파일의 `FEW_SHOT`에 대본 형식(`[상황 N - …]`, `[대화 N - …]`, `유저:`, `{캐릭터명}:`)으로 쓴다. 후반부 내용이면 제목 끝에 `(루프N부터)`를 붙인다.
- **예시 개수:** 캐릭터당 7개 안팎을 유지한다. 늘어날수록 예시를 베끼고 규칙이 묻히는 문제가 다시 생긴다.
- **보관 예시 다시 쓰기:** `few_shot_archive/`에서 블록을 복사해 `FEW_SHOT`에 붙인다.
- **조사:** `{player_name}` 뒤 조사는 자동 보정되므로 신경 쓰지 않아도 된다.
- **루프별 공개 범위 변경:** `base.py`의 `_LOOP_RESTRICTION`만 고친다.

## 6. 남은 과제

- 차서연은 대화 중 "이서진 선생님"(성 포함)과 "서진 선생님"이 섞인다. 대화가 격해지며 호칭이 바뀌는 건 캐릭터상 자연스러워서 그대로 둔다.
- 실제 플레이로 루프별 말투와 정보 노출 정도를 확인할 것.
