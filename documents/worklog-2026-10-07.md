## 8. 엔딩 배경음 · 자동 재시작 (PR #116)

- 엔딩 진입 시 `frontend/audio/ending-static.mp3`(5분, 9.6MB) 재생
- 끝나기 3초 전 SYSTEM 팝업 "3초 후 루프가 다시 시작됩니다." → 음원이 끝나면 기록 초기화 후 시작 페이지로. '눈을 뜬다' 버튼은 유지
- **자동 재생이 막힌 경우** (주로 iPhone Safari): SYSTEM 팝업 "화면을 터치하세요."를 띄우고 엔딩을 멈춘다. 30초 카운트다운 후 소리 없이 자동 시작. 소리가 안 나도 엔딩 시작 후 5분이 지나면 이동한다

**결정 배경 — 브라우저 자동 재생 정책**
- 사용자가 그 페이지에서 화면을 누르기 전에는 소리를 낼 수 없다. 음원 파일이든 Web Audio든 똑같이 적용된다
- iPhone Safari는 페이지가 바뀌면 이전 클릭 기록이 초기화된다. 엔딩은 페이지 이동으로 들어오므로 대부분 막힌다
- 같은 페이지 안에서 엔딩을 불러오는 구조(SPA)로 바꾸는 안도 검토했지만, 범인 지목 경로에서만 효과가 있고(채팅 중 사망·시간 초과·포기 경로는 여전히 막힘) 작업량이 커서 보류했다
- 그래서 **막혔을 때만 터치 팝업 + 엔딩 멈춤** 방식을 택했다

## 11. 모바일 화면 고정형 레이아웃 정리 (PR #117)

**노트북 대응 방식 결정:** 가운데 모바일 화면 고정형(폭 430px)을 유지한다. 스토리 게임이라 기기마다 같은 구도로 보이는 것이 중요해서, 반응형 레이아웃 전환이나 비율 고정 확대 방식은 쓰지 않는다.

- 게임 화면 밖에만 보이던 효과 레이어 삭제 (오프닝: 안개·비네트·핏빛 / 버튼룸: 안개). 실제로 보이는 스캔라인·버튼룸 비네트는 게임 화면 안으로 이동
- 모든 화면에서 바탕색 = 게임 화면 색
- `position: fixed` 요소(커튼, 플래시, 팝업, 전환 오버레이)를 게임 화면 안의 `absolute`로 변경. `fixed`는 부모 상자를 무시하고 브라우저 창 기준이라, 노트북에서 430px 밖까지 덮었다. 이제 프로젝트에 `position: fixed`가 없다
- 게임 화면 최대 폭 430px로 통일 (오프닝·버튼룸 460px → 430px)
- 채팅 입력칸 `min-width: 0`: iPhone Safari에서 입력칸이 기본 최소 폭 아래로 줄지 않아 보내기 버튼을 화면 밖으로 밀어내던 문제
- 채팅룸 하단 안전 여백 중복 제거, 320px에서 헤더 태그와 버튼 겹침 수정

## 12. iPhone 실기기 대응 (PR #118, #119)

| 문제 | 원인 | 수정 |
|---|---|---|
| 오프닝 영상이 상태바 뒤까지 올라가 위로 치우침 | `viewport-fit=cover`로 상태바·Dynamic Island 영역까지 그려지는데, Safari 탭에서는 `env(safe-area-inset-top)`이 0이라 피할 수 없었음 | 전 페이지 `viewport-fit=cover` 제거 (#119). 화면 전환 시 바탕색을 현재 화면색에 맞춤 (#118) |
| 페이지 전체가 스크롤됨 | 오프닝·버튼룸 `body`의 `min-height: 100vh`. iOS의 100vh는 툴바에 가려지는 부분까지 포함 | `html, body { height: 100%; overflow: hidden }` (#119) |
| 버튼룸 이미지가 위에 붙어 아래가 비어 보임 | 이미지 영역이 `height: 50vh`로 위에 고정 | 대사 패널 위 공간의 세로 가운데에 배치 + 위아래 그라데이션. 패널 높이는 `button.js`가 측정해 `--panel-h`로 전달 (#118) |
| 채팅룸 입장 시 음악이 꺼져 있음 | 자동 재생 정책 | 막히면 "음악을 재생하세요" 팝업. 팝업 중 타이머 정지 (#118) |
| 키보드가 열리면 화면 전체가 밀려 올라감 | iOS가 입력창을 보이게 하려고 페이지 전체를 스크롤 | `visualViewport` 높이에 맞춰 `#app` 높이를 줄이고 페이지 스크롤을 되돌림. Android용 `interactive-widget=resizes-content` (#118) |

- 타이머 정지·재개를 `pauseGameTimer()` / `resumeGameTimer()`로 공용화 (포기하기·음악 재생 팝업이 함께 사용)
- 이 문제들은 Chrome의 모바일 크기 보기에서는 재현되지 않아, 실기기 확인이 필요하다

## 13. 닉네임 · 호칭 · 성별 '기타' (PR 전, 커밋 `066c6d0`)

**배경:** 캐릭터와 주인공이 모두 한국인 설정이다. 그런데 영문 닉네임이나 두 글자 닉네임을 넣으면 엄마가 "ohn야", "하야"처럼 어색하게 불렀다.

**닉네임 한글 제한**
- 완성형 한글(가~힣)만 허용. 영문·숫자·공백·특수문자가 섞이면 시작 버튼 비활성화
- 입력칸 아래에 "닉네임은 한글만 사용할 수 있습니다." 상시 표시, 잘못된 문자가 섞이면 빨간색 강조 (조합 중인 자음·모음은 오류로 보지 않음)
- 이름·성별이 없으면 버튼이 막히는 처리는 원래 구현되어 있었다. 여기에 한글 조건을 추가했다

**호칭 개선** (`base.py`)
- `get_first_name`: 세 글자 → 첫 글자(성) 제거, 네 글자 + 두 글자 성(남궁·제갈 등) → 두 글자 제거, 두 글자 이하 → 그대로 (닉네임일 수 있어서)
- `get_call_name` 추가: 받침이 있으면 '아', 없으면 '야' (서진아, 재희야). 엄마·차서연 프롬프트의 `{first_name}야`/`{first_name}아` 11곳을 `{call_name}`으로 교체
